# Security Policy

## Supported Versions

Currently, only the latest version of AgentShield is supported with security updates.

## Reporting a Vulnerability

If you discover a security vulnerability in AgentShield, please follow these steps:

1. **Do not create a public issue** - Security vulnerabilities should be reported privately
2. **Send details to the maintainers** - Contact the project maintainers privately
3. **Provide as much detail as possible** - Include steps to reproduce, expected vs. actual behavior, and potential impact
4. **Allow time for remediation** - Give the maintainers time to investigate and address the issue

## What to Include in Your Report

- A clear description of the vulnerability
- Steps to reproduce the issue
- Affected versions
- Potential impact
- Any proposed mitigation (if applicable)

## Disclosure Process

Once a vulnerability is reported:

1. The maintainers will acknowledge receipt within 48 hours
2. The maintainers will investigate and assess the severity
3. A fix will be developed and tested
4. A security advisory will be published
5. The fix will be released as a security update

## Security Best Practices

When using AgentShield:

- Never commit credentials or sensitive data to your repository
- Use the policy engine to enforce execution limits
- Regularly update to the latest version
- Review test results carefully
- Understand the limitations documented in the security documentation

## Security Acknowledgments

We thank all security researchers who help make AgentShield more secure by reporting vulnerabilities responsibly.
